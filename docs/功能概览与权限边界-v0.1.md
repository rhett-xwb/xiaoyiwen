# 校易问：功能概览与权限边界

版本：v0.1（需求讨论稿）  
日期：2026-10-28  
首期场景：珠海科技学院

## 1. 产品定位

面向在校学生的校园制度智能问答平台。基于学生手册、校规校纪、奖助与资金申请办法、项目申报通知等经过审核的材料，提供有原文依据的回答及办事指引。

核心流程：提出问题 → 必要时补充条件 → 检索有权访问的有效材料 → 生成答案 → 查看引用原文 → 反馈问题。

首期为独立求职演示项目，不代表学校官方服务。正式接入校方身份与数据需另行明确授权。

## 2. 第一版范围

| 业务领域 | 第一版内容 | 材料要求 |
|---|---|---|
| 校规校纪 | 行为规范、违纪处理、申诉等条款问答 | 学生手册或正式制度 |
| 学生事务 | 手册中已有的学籍、住宿等事项查询 | 以实际获得材料为准 |
| 资金申请 | 奖助、贷款、活动经费的条件、材料与流程查询 | 按实际材料逐项开放 |
| 项目审批 | 项目申报、立项、结项等流程与材料查询 | 正式管理办法及年度通知 |

第一版交付“问答与指引”，不办理真实资金申请、不执行审批、不决定学生资格或处分结果、不查询个人成绩或申请进度。没有对应材料的主题不展示为已支持能力。

## 3. 用户角色

| 角色 | 职责 | 边界 |
|---|---|---|
| 访客 | 查看产品介绍、示例问题 | 默认不能使用真实知识库问答或浏览文档；演示使用明确标记的示例 |
| 学生用户 | 问答、查看获准原文、管理个人会话、提交反馈 | 不能查看他人会话、未发布文档或管理功能 |
| 知识管理员 | 导入材料、维护元数据、修正解析、发布与停用、处理反馈、查看聚合统计 | 只能管理分配的知识库；不能分配系统角色，不能默认读取学生完整会话 |
| 系统管理员 | 账号与角色、知识库授权、系统配置、运行监控、审计 | 不因系统管理身份自动获得所有文档和私人会话的业务阅读权限 |

教师身份第一版不单设角色：普通查询使用普通用户权限；负责制度维护时，显式授予知识管理员角色。正式部署可由校方指定人员承担知识管理员职责。

## 4. 功能清单

P0 为第一版必须，P1 为后续增强。

| 编号 | 功能 | 优先级 | 需求与边界 |
|---|---|---|---|
| F01 | 登录与用户管理 | P0 | 演示采用本地账号；不声称完成校内身份认证；用户不能自行选择管理员角色 |
| F02 | 智能问答 | P0 | 流式回答，支持取消；默认仅检索已发布且当前用户有权访问的材料 |
| F03 | 多轮追问 | P0 | 支持“需要什么材料”等上下文问题；缺少年级、项目类型等关键条件时追问，不擅自假定 |
| F04 | 引用与原文预览 | P0 | 关键结论关联文件、条款或章节；PDF 可定位页码，网页提供来源链接，其他格式定位片段；无页码时不编造 |
| F05 | 办事指引 | P0 | 按条件、材料、步骤、时间、部门组织回答；来源未明确的字段标记未找到依据 |
| F06 | 会话管理 | P0 | 新建、查看、删除个人会话；不同用户数据隔离；删除后不再用于后续问答 |
| F07 | 反馈 | P0 | 标记不准确、引用错误、过期或缺资料；默认只提交目标问题、目标回答、引用与用户补充，不附整段历史 |
| F08 | 文档导入 | P0 | 支持文字型 PDF 与 DOCX，限制类型与大小；导入失败可查看原因并重试 |
| F09 | 解析与分块检查 | P0 | 保留章节、条款、附件关系，管理员可预览并修正；扫描件无法提取文本时明确提示待 OCR 处理 |
| F10 | 文档与版本管理 | P0 | 维护来源、发布部门、版本、适用范围、发布时间、生效/失效时间和替代关系；未知字段允许明确标记未知 |
| F11 | 发布与停用 | P0 | 发布前预览；未发布、停用及已失效文档不进入默认问答；更新后检查索引就绪再切换版本 |
| F12 | 权限与审计 | P0 | 后端校验角色、知识库范围及资源归属；记录登录、授权、发布、停用、删除等关键事件 |
| F13 | 基础统计 | P0 | 查看问题量、反馈量、无依据回答比例等聚合信息，不展示个人完整聊天记录 |
| F14 | OCR 与复杂表格 | P1 | 扫描手册识别、表格还原；若核心手册只有扫描版，OCR 调整为 P0 |
| F15 | 历史制度查询 | P1 | 显式选择历史时点，清楚标记历史版本；第一版不混用新旧版本 |
| F16 | 自动同步与到期提醒 | P1 | 同步仍需审核发布，不直接将抓取内容投入问答 |
| F17 | 统一身份认证 | P1 | 获得授权后接入校方身份系统，使用可信身份属性控制访问 |

## 5. 权限矩阵

“范围内”表示显式分配的知识库范围，“本人”表示资源所有者。

| 操作 | 访客 | 学生用户 | 知识管理员 | 系统管理员 |
|---|---|---|---|---|
| 查看产品介绍与示例 | 是 | 是 | 是 | 是 |
| 真实知识库问答/查看引用 | 否 | 已授权范围 | 已授权范围 | 已授权范围 |
| 查看与删除会话 | 否 | 本人 | 本人 | 本人 |
| 提交反馈 | 否 | 本人 | 本人 | 本人 |
| 查看反馈处理状态 | 否 | 本人 | 范围内工单 | 本人；兼任知识管理时可处理范围内工单 |
| 导入、修订、发布、停用文档 | 否 | 否 | 范围内 | 需另授知识管理权限 |
| 处理反馈及聚合统计 | 否 | 否 | 范围内 | 需另授知识管理权限 |
| 账号、角色及知识库授权 | 否 | 否 | 否 | 是 |
| 模型配置与运行监控 | 否 | 否 | 否 | 是 |
| 查看系统审计 | 否 | 否 | 否 | 是；日志不默认保存问答正文 |

系统管理员具备敏感的授权能力，其授权变更必须记录审计。应用层业务隔离不能保证服务器或数据库操作者在基础设施层无法访问数据。

## 6. 文档与数据访问边界

### 6.1 文档分级

- 公开资料：来自公开官方网站，平台第一版仍要求登录后问答。
- 校内资料：仅向已验证或演示中由管理员分配的校内用户开放；登录本身不等于校内身份验证。
- 指定范围资料：限定学院或指定用户组，通过管理员维护的可信属性授权，不根据用户聊天中的自述扩大权限。

第一版不导入包含个人身份证、银行卡、个人处分详情或申请人隐私的业务档案。

### 6.2 检索与引用

- 授权过滤在检索阶段执行，未经授权的片段不能进入重排、模型上下文或答案。
- 文档列表、预览、引用、下载与后续追问都重新校验权限；知道文档 ID 或 URL 不构成授权。
- 第一版引用提供受控预览，不提供原始文件下载；预览接口每次鉴权。
- 文档停用或用户权限撤销后，原有链接不可继续访问；历史会话展示时隐藏已失权证据关联的回答正文和引用，保留不可用提示。
- 对无法建立证据关联的旧回答，在权限变化后采取保守隐藏；不承诺撤回用户此前已保存的内容。
- 第一版不使用跨用户的答案缓存；若后续引入，缓存需包含授权范围和文档版本并支持失效。

### 6.3 会话与反馈

- 会话只能由本人通过业务接口访问，管理员不设“查看所有聊天”入口。
- 用户提交反馈前可预览提交内容，并提示避免提交敏感个人信息。
- 运行日志不记录密钥和完整问答正文；发送外部模型的内容限于必要的问题、上下文与获准片段。
- 删除会话后撤销在线可见性并排除后续上下文使用；数据库清理、备份保留与外部模型留存规则需在部署前明确，不能宣称即时抹除所有副本。

## 7. 答案行为规则

| 情况 | 预期表现 |
|---|---|
| 有直接依据 | 回答并引用支持结论的条款 |
| 需要多份材料 | 分别引用管理办法与通知，明确各自支撑的内容 |
| 条件不足 | 先问缺少的关键条件，再提供匹配答案 |
| 无依据或超出范围 | 明确未找到，不凭常识补出学校规定 |
| 年度时限不明 | 区分长期办法与当年通知，不沿用往年截止日期 |
| 文件冲突 | 展示冲突来源与版本信息；替代关系未确认时不自行宣布哪份有效 |
| 用户要求作审批决定 | 仅给出条款和指引，说明最终结果需由负责部门确认 |
| 文档夹带模型指令 | 将其视为待引用的数据，不执行其中要求泄露信息、忽略权限或改变系统规则的指令 |

回答不展示缺乏校准依据的“可信度百分比”。可以展示“已找到依据”“条件待补充”“未找到充分依据”等证据状态。

## 8. 文档生命周期

上传 → 解析中 → 待校验 → 待发布 → 已发布 → 停用/被替代。

解析失败可重试；待校验和待发布材料不能被普通问答检索。新版本独立保存，明确替代关系；删除草稿可直接执行，已发布文档优先停用保留审计。第一版允许知识管理员自行校验并发布，不引入额外审核角色；正式部署可扩展双人审核。

## 9. 页面范围

学生端：登录页、问答首页、会话历史、引用原文侧栏、反馈入口与个人反馈状态。

管理端：知识库列表、文档导入、解析预览、版本与发布管理、反馈处理、聚合统计。

系统端：用户与角色、知识库授权、模型连接配置、运行状态、审计记录。密钥仅后台保存，前端不返回完整值。

## 10. 第一版验收

1. 至少一份真实手册或正式制度完成导入、校验、发布、问答和原文定位。
2. 建立至少 30 道带人工标准依据的问题，覆盖直接查询、跨条款、追问、无依据、年度通知和版本冲突；记录检索命中、答案依据及引用定位结果，失败项可复现。
3. 发布、停用和版本切换后，默认检索使用正确材料；未知生效日期不自动推定为最新有效。
4. 学生无法通过修改会话 ID、文档 ID 或引用地址查看其他用户或越权资料；权限撤销后的历史会话与引用也受控。
5. 管理员只能管理授权知识库；普通用户不能调用发布、授权或配置接口。
6. 缺乏来源时不会生成虚构的金额、期限、办理部门或条款编号。
7. 反馈不附带无关会话；删除后的个人会话不可再次通过业务接口访问。
8. 解析、模型或检索服务失败时给出可理解的失败提示，不伪装成正常的无依据回答。

性能目标在样本量、部署配置和模型确定后制定，展示首字延迟、完整回答耗时及失败率的实测结果。

## 11. 尚需确认

- 学生手册电子版、年份与实际适用对象。
- 资金申请优先支持奖助学金、社团活动经费还是大创经费。
- 项目审批优先支持大创项目、社团活动还是其他学生项目。
- 开发周期、已有技术基础及可用模型接口。

目前默认：面向学生，采用演示账号；知识管理员管理已授权材料；先完成手册问答与引用，再扩展有正式材料的申请/审批指引。
