# 校易问阶段开发计划

## 1. 当前状态与执行方式

- 已完成：Git 初始化、项目目录和空文件搭建、需求与权限梳理、初步架构文档。
- 已确认：Java + Spring Boot 模块化单体、Vue 3、MySQL、Qdrant、容器化 PaddleOCR、Docker 持久化卷；回答和向量模型使用外部 API。
- 尚未完成：应用实现、数据库建表、容器配置、服务启动、核心链路验证及测试。
- 用户选择先跳过独立技术验证，不把解析能力和检索效果视为已验证；相关验证纳入对应开发阶段。
- 不预设工期。模型服务、Docker 可用性、OCR 资源等依赖明确后再估算。

本计划是任务安排，不代表批准所有待定技术选型或立即执行全部阶段。按当前协作约定：用户下达具体阶段或任务指令，确认存在歧义的选择后再实施；未确认的业务和技术细节不得自行补全。

任务状态使用：未开始、进行中、待确认、已完成。只有交付物和验收实际完成，才能标记已完成。

## 2. 阶段总览

| 阶段 | 目标 | 当前状态 | 主要依赖 |
|---|---|---|---|
| P0 需求与架构基线 | 汇总已确认规则、区分待定项 | 进行中 | 已有需求、权限、架构 |
| P1 详细设计与契约 | 确定模型、状态、接口及页面行为 | 未开始 | P0 |
| P2 容器环境与工程骨架 | 在容器中构建、启动前后端及基础服务 | 未开始 | P1 的版本及组件决策 |
| P3 账号、权限与审计 | 建立后续业务的后端权限基础 | 未开始 | P2、身份规则与接口设计 |
| P4 手册导入与校验 | 跑通格式处理、AI 初检、人工修订复核 | 未开始 | P3、OCR 和 AI 接入决策 |

前端按阶段逐步接入真实接口，不等后端全部完成才开始联调。每阶段验证自身范围，最后综合验收不替代阶段检查。

## 3. P0：需求与架构基线

任务：

- 核对 `requirements.md` 与 `permissions.md`，补齐已确认的账号、匿名问答及手册访问需求引用。
- 在 `architecture.md` 记录模块化单体选择，保留其余待定决策。
- 登记示例手册来源、具体文件和版本；实际读取文件需由用户另行下达任务。
- 列出影响下一阶段的决策，不要求一次解决所有远期细节。

交付物：一致的需求、权限与架构基线，以及待确认清单。

验收：文档之间没有互相矛盾的访问规则；未实现能力和未验证技术明确标记，不写成项目成果。

## 4. P1：详细设计与契约

任务：

- 确定 Java、Spring Boot、Vue、MySQL、Qdrant、OCR 等版本及兼容关系。
- 确定回答模型、向量模型、AI 初检接入方案；不预设使用 Spring AI 或其他框架。
- 设计账号、授权、文件、手册版本、解析正文、检查结果、索引关联、留言及审计等数据关系。
- 设计文档处理、校验、发布、停用、逻辑删除及彻底删除的状态和限制。
- 明确后台任务同步或异步、超时、重试，以及 MySQL 与 Qdrant 的一致性策略；不默认引入 Redis 或消息中间件。
- 定义接口请求响应、鉴权、错误及问答传输方式。
- 确定页面及加载、失败、无依据、无权限等交互状态。

交付物：`data-model.md`、`rag-design.md`、`api/openapi.yaml`、`ui-spec.md`，以及更新后的架构决策。

验收：第一条业务链路的输入输出、状态、访问边界均能据此实现；关键待定项已解决，后续项保留待定。

## 5. P2：容器环境与工程骨架

任务：

- 经用户下达检查指令后检查 Docker 可用性；缺少环境时明确反馈，不默认为已安装。
- 编写容器构建和编排配置，提供前后端开发、构建与运行环境。
- 配置 MySQL、Qdrant、OCR 的容器网络、健康检查及持久化。
- 创建 Spring Boot 和 Vue 工程，建立基础接口与前端调用。
- 配置数据库迁移入口、环境变量示例及秘密配置注入方式。
- 为后续 OCR 处理准备具体组件及模型资源，实际资源消耗记录为实测结果。

交付物：工程骨架、容器配置、环境示例、初版启动说明。

验收：不调用宿主机 Java、Maven、Node.js、Python 或数据库即可完成构建和启动；前后端连通，MySQL 和 Qdrant 可访问；OCR 达到已定义的服务健康检查要求，转换正确性留在 P4 验证；重建应用容器不丢持久化数据。

## 6. P3：账号、权限与审计

任务：

- 初始化演示学生名单、绑定邮箱及部署时设置的最高权限账号。
- 实现学号、初始密码和演示邮箱验证激活；支持改密但不强制。
- 实现登录、退出、账号禁用和已有登录状态即时撤销。
- 实现最高权限管理员的操作授权，以及后端权限校验。
- 记录关键管理操作审计；不提供管理员读取所有私人会话的入口。
- 接入登录、激活、改密及必要管理页面。

交付物：身份权限基础功能、演示账号初始化方式、审计能力及相应页面。

验收：学生不能调用管理接口；普通管理员只能执行获授权操作；禁用后已有登录状态失效；演示验证不冒充学校真实身份验证；核心权限通过正常和越权场景检查。

## 7. P4：手册导入、AI 初检与人工复核

任务：

- 实现 MD、DOCX、DOC、PDF 上传及 100 MB 上限检查，保留上传文件。
- 实现 PDF 经容器化 PaddleOCR 转 Markdown；验证 DOC、DOCX 内容提取；处理失败显示原因。
- 支持人工转换 MD 的来源说明，不提供不存在的原 PDF。
- 实现 AI 疑点检查、管理员正文预览、在线修改和人工复核。
- 修改后重新初检、复核；原文件不被在线编辑覆盖。
- 接入上传、处理状态、疑点查看和正文校验页面。

交付物：格式处理链路、AI 检查与人工复核功能，真实样本处理记录。

验收：逐格式验证样本处理，不以“进程启动”替代解析正确性；AI 未发现问题仍需人工复核；修改后的正文有区别标记；超限文件拒绝；未发布资料不进入学生问答。

若解析或 OCR 效果不能满足要求，记录实际问题并由用户确认调整方案，不能未经确认删除已承诺格式。

## 8. P5：RAG 问答与发布治理

任务：

- 按已确认方案生成片段、来源定位及外部模型向量，建立 Qdrant 索引。
- 完成检索、回答和引用校验；无依据时说明未找到。
- 完成手动发布与索引就绪检查；失败不得把未就绪版本作为可用版本。
- 完成新版替换、停用、逻辑删除及最高权限彻底删除，遵循 P1 确认的关联清理规则。
- 已发布正文修改前强制停用，修改后重新检查、复核及手动发布。
- 完成匿名 IP 每日限额、概括性回答限制，以及登录学生的引用、预览和下载。
- 接入问答页、引用查看、文件访问和版本管理页面。
- 建立人工核对的问题样本，记录检索命中、答案依据及引用定位情况；数量和通过标准在执行前确认。

交付物：上传、校验、发布、提问、带依据回答及引用查看的第一条完整链路；评估记录。

验收：匿名响应与原文接口不泄露受限片段；登录学生只能访问有效发布资料；停用与逻辑删除立即影响检索及文件访问；只上传新版不影响旧版；引用支撑回答；无依据、模型失败和检索失败能够区分。原文索取、停用版本及修改正文的回归场景有实际记录。

## 9. P6：留言、附件和管理员回复

任务：

- 仅允许登录且完成改密的用户提交。
- 支持 MD、TXT、DOCX、PDF，每次最多 3 个附件，每个不超过 10 MB。
- 每人每天成功提交最多 3 次，北京时间零点重置；失败不扣额度。
- 所有管理员可查看用户主动提交的内容并选择回复；学生仅查看本人留言对应回复。
- 接入用户留言与回复页面、管理员处理页面。

交付物：留言、附件、回复完整功能及配额控制。

验收：未改密不能提交；越权查看本人以外回复被拒绝；并发提交不突破每日额度；附件数量、格式和大小边界正确；管理员不能据此访问用户其他问答记录。

## 10. P7：综合验收与交付

任务：

- 按需求逐项验收，复查角色授权、文件接口、停用版本和账号禁用。
- 使用标准问题检查实际问答质量，记录失败案例及修复情况。
- 验证全新环境初始化、容器重启、持久化、配置缺失和外部服务异常。
- 编写 README、部署说明和演示操作步骤，标注示例手册真实来源及非官方性质。
- 记录实际环境与耗时，不编造并发量、用户量、准确率或测试数量。
- 基于实际交付结果再更新简历描述。

交付物：可复现部署的第一版、验收记录、已知限制、演示资料。

验收：按 README 可以在具备 Docker 的环境构建运行；核心场景可复现；未完成和未验证项如实列明；密钥及私人数据不进入代码仓库。
